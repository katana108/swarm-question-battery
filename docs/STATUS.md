## How a run works, if you need to run more
1. `src/assemble_prompt.py <chunk.txt>` builds instructions + questions + codebook + chunk (checks the freeze first).
2. `src/run_coder.py <in_dir> <out_dir>` (Anthropic) or `src/run_coder_openai.py` (OpenAI/Luna) sends each chunk,
   saves `<id>.json`, resumes safely, stops at the `$50`/person cap in `config.yaml`, writes `coder_meta.json`.
3. `src/review.py <in_dir> <out_dir>` validates quotes and prints a per-question summary.
4. `src/agreement.py` / `src/analyze.py` compute kappa and build the long-format tables + `results/ANALYSIS.md`.
Both API keys live in a git-ignored `.env` in the repo root (never printed, never committed). The Anthropic key
needs `ANTHROPIC_WORKSPACE_ID` set too (see `.env`) - without it the API 400s.

## Open items / known issues
- **Luna + `no_channel_provided`**: the codebook doesn't list it among codes that need no quote, so Luna's answers
  using it get dropped by the validator (6 wiki chunks affected). Real bug, not fixed yet - would be a v0.6 change.
- **Q3 act_types and Q10 pattern** are the least reliable fields on wiki agreement (kappa 0.46 and 0.32). Worth
  tightening the codebook definitions before trusting cross-dataset comparisons on those two.
- **Refusals are not random**: the safety stop fires more on technical/exploit-dense chunks, so coded chunks
  skew away from the most technical pages. State this as a limit, don't work around the stop.
- **No human-coded gold set**: cross-vendor coder agreement is the only reliability evidence so far.
